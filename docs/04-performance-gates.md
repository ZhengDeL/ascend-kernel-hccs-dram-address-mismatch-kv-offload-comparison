# 5% 性能门槛与正确性验收

用户于 2026-10-23 明确：性能最多允许损失 **5%**。以下是约定的测试门槛和计划，尚无该服务器实测成绩。

| 指标 | 候选方案相对同条件基线 |
| --- | --- |
| 成功请求的输出 token/s、满足 SLA 的请求/s | 不低于 95% |
| P99 TTFT | 不超过 105% |
| P99 TPOT | 不超过 105% |
| 内容/状态正确性 | 不接受由卸载造成的错误、缺失混合状态、空流或请求丢失 |

5% 同时约束吞吐和尾延迟，不用均值改善掩盖 P99 回退。零失败为本轮样本通过标准，不能表述成生产故障率必为零。样本不足时 P99 不稳定，应报告样本量和分布，而非仅给一个百分数。

## 两种基线必须分开

- **现场业务基线 B0**：同两台服务器、相同官方 PD 并行、模型和 rc2 镜像，关闭 Pool 卸载，但保持 P→D MooncakeV2。用于判断加 MemCache 的业务收益和代价。
- **卸载实现基线 B1**：若同机 `device_sdma` 可运行，用它比较候选软件路径；若不可运行，写“不可测”，不制造本机原生带宽数据。另一台参考机的直访结果只能作为参考，不能用来证明本机≤5%。

冷缓存/0%复用用于量化纯额外开销；热缓存用于检验节省 Prefill 是否抵消搬运成本。基线与候选都用相同前缀内容、token数、缓存冷热和命中口径。不开 Pool 的 B0 可以保留普通 APC，但要明确是否命中 HBM，不把 HBM 命中当外部池收益。

## 测试层次

1. **分配与搬运**：同机 H2D/D2H、单机 Provider/Proxy、两机远端通路，先小容量 CRC，再逐级容量。块大小至少 8KiB/1MiB/8MiB/64MiB，补充真实模型 KV group / block 大小。分别记录双向有效 GB/s、首次注册、稳态、单流与并发、CPU、NUMA、HBM和Host峰值。
2. **Store**：同一已完成写入的数据被独立消费者取回；覆盖覆盖写、未命中、淘汰、容量满，记录返回值和实际字节。服务重启/断链属于维护窗口故障试验，不自动对生产执行。
3. **模型状态**：GLM-5.3-Flash 的 SFA / indexer pool / tail / KDA / conv state 必须整体对应。验证长前缀命中后继续生成与无卸载正确性，不仅检查普通 attention 张量。固定采样/seed，保留原始 token IDs 或适用的数值误差判据；MTP 开关保持一致。
4. **业务**：普通/流式/tool call、冷/热前缀、并发1与实际目标并发，至少覆盖短上下文、8K、32K和实际长上下文。在端到端能力未通过前不宣称完整128K/1M接受。
5. **稳定性**：明确请求数、时间、池水位和负载；监视 kernel/plog、HCCS错误、分配/Get失败、重算/回退。HTTP200与health只用于就绪检查。

正式性能每条件至少三轮，建议ABBA或交错顺序，先完成预热、再计时；冻结镜像digest、模型metadata哈希、全部参数、数据集哈希、输入输出token数、请求率/并发、CPU绑定、驱动和网络状态。尾延迟需足够样本，接近5%边界且波动覆盖阈值时结论为待复测。排队、失败和超时单独报告，禁止只筛快请求。

## 路径证明与 Pool 命中口径

记录实际 `device_sdma` / Host / Buffer Pool 协议、初始化日志和 HCCS/NIC 计数前后差异，防止静默走TCP或重算。vLLM token级外部命中、Store对象/操作级命中、设备传输字节不是同一单位，分别报告。MultiConnector 场景下需要区分 P→D 通路与 Prefill Store，不把全局 cached_tokens 自动归给 MemCache。

## 为什么不能先保证 host_shm 达标

官方 MemCache A3 备选文档存在 PCIe 单机池化案例，但其硬件/模型/版本与本任务不同，且部分长输入条件较无池基线有退化。源码有该路径只证明实现存在。NUMA绑定、批量拷贝、复用 pinned buffer、流水与overlap需要逐项测量；不能在没有基线时承诺损耗≤5%。

任何优化仅修改一个可解释变量；影响超出本任务的 BIOS、交换机或共享 Meta 不作为默认试验动作。
